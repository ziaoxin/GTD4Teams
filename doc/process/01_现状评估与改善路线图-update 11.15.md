**顺带兑现了原路线图的两项前置条件：**
- 0-2「自助注册收紧」→ 从"配 `.env` 关开关"升级为"代码里根本没有这个端点"。原文 §10.3 说"配 `.env` 有三条绕开路径"，现在这条路不存在了。

**这次变更过程中抓到的三个真 bug（单元测试全绿也测不出来）：**
1. **系统管理员建 `member` 反而成功、建 `admin` 反而 400** —— 核心权限语义反转。单元测试全绿，因为测试本身固化了同样的错误语义；只有容器端到端才暴露。

3. 改密闸门白名单常量 6 条只写了 3 条 —— 静默不一致，不影响当前行为但契约对不上。

> 教训（值得写进项目纪律）：**绿色如果来自不可靠的断言，比红色更危险。** 这次的价值不在于修了三个 bug，而在于证明了"单测全绿 + 端到端跑一遍"这两层缺一不可。

## 4. 新发现：一处文档-代码漂移（需要你裁决）

### D-01 · `--import` 的跨版本行为，实现与最终裁决相反

| | 内容 |
|---|---|
| **文档怎么写** | `05` §13.9 记录的主理人最终裁决：**不做列裁剪**，改为捕获 `no such column` → 抛 `IMPORT_SCHEMA_MISMATCH` → 提示"请先 `--check` 升级结构再导入"。理由是"静默丢列比明确失败更危险"（新备份导入旧库会静默丢失 `is_system_admin`，还原后实例零管理员而操作者看到"导入成功"）。 |
| **代码怎么做** | `store.import_all` 实际是**按目标库真实列过滤**（`real_columns = _table_columns(conn, table)` → `cols = [c for c in row.keys() if c in real_columns]`），并且注释写着"不是安全边界，只解决健壮性"。**全仓无 `IMPORT_SCHEMA_MISMATCH`。** |
| **怎么发生的** | 后端成员在收到"撤销白名单"的裁决消息之前就撞了 429 中断，实现停留在中间版本。 |
| **实际风险** | 新代备份 → 旧结构库：**静默成功但丢两列** → 管理员标记归零 → 无人能建号。运维看到"导入成功"，不会去查为什么建号按钮没了。 |

**两个选项，请你裁决：**

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐，回到原裁决）** | 去掉列过滤，加 `IMPORT_SCHEMA_MISMATCH` 明确报错；`09` 灾难恢复流程强制"导入前先 `--check`" | 约 15 行代码 + 1 条测试；运维多一步 `--check` |
| **B（承认现状）** | 保留按真实列过滤，把 `05` §13.9 的结论改回"健壮性"定性，并在 `09` 写明"导入后必须检查系统管理员数量" | 零代码；但留下一类"静默降级"，且与已写的决策理由矛盾 |

> 我倾向 A：**一个明确的失败 + 一句"先升级结构"，比一次成功的静默降级安全得多。** 但这是你的系统，B 也是合理选择——只要 `09` 补上"导入后核对管理员数量"这一步。
