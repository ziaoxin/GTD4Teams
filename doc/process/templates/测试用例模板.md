# 模板 · 测试用例

> 维护人：质量保障 ｜ 上位文档：`07_测试体系与各阶段验收标准.md` §8.2、§9.2 ｜ 编号规则：`00_开发流程总纲.md` §5.2
> **用法**：复制 §3 的「用例卡」逐条填写；多条用例用 §4 的汇总表登记；示例见 §5。本模板可直接打印/粘贴进测试报告。

---

## 1. 编号规则

| 项 | 规则 |
|---|---|
| 格式 | `TC-<域>-NNN`（NNN 为三位序号，按域独立递增，不复用、不跳号） |
| 示例 | `TC-AUTH-013`、`TC-PERM-003`、`TC-CON-001` |
| 域缩写 | `AUTH` 认证会话 / `PERM` 权限 / `TEAM` 团队与成员 / `ITEM` 工作项 / `BOARD` 看板 / `REVIEW` 复盘 / `SHIFT` 值班 / `ASSET` 资源台账 / `GTD` 个人 GTD / `STATIC` 静态托管 / `LLM` AI 通道 / `BACKUP` 备份还原 / `RELEASE` 发布 / `MIG` 迁移 / `PERF` 性能 / `COMPAT` 兼容性 / `BOOT` 启动集成 / `RENDER` 渲染 / `FLOW` 业务闭环 |
| 追溯要求 | 每条用例必须填 `关联需求 REQ-xxx`；无需求的存量用例填 `存量补课` 并在备注说明（总纲 §8） |
| 与脚本的对应 | 自动化用例在「自动化脚本」栏写明 `tests/test_api.py` / `.smoke/*.mjs` / `deploy/smoke.sh` 及函数名；手工用例写 `手工` |

## 2. 字段表

| 字段 | 必填 | 说明 |
|---|---|---|
| 用例编号 | ✅ | `TC-<域>-NNN`，唯一 |
| 所属功能域 | ✅ | 对应 `07` §2 覆盖矩阵的功能域 |
| 关联需求 / 规则 | ✅ | `REQ-xxx` / `BR-xxx` / `EX-xxx`，或「存量补课」 |
| 测试类型 | ✅ | 单元 / 接口 / 集成 / E2E / 验收（五类，见 `07` §1.1） |
| 用例类别 | ✅ | 正常 / 边界 / 异常 / 权限 / 并发 / 重复请求（六类，严格模式必填） |
| 优先级 | ✅ | P0 / P1 / P2 / P3（定义见 `07` §5.1） |
| 前置条件 | ✅ | 账号、团队、数据状态、环境（含 `GTD_TRUST_PROXY` 等开关取值） |
| 测试步骤 | ✅ | 编号列出，每步一个动作，可复现 |
| 预期结果 | ✅ | **可判定**：写明具体状态码 / 返回值 / 数据状态，禁止「正常」「没问题」 |
| 实际结果 | 执行时填 | 照录，不修饰 |
| 结论 | ✅ | 通过 / 失败 / 阻塞 / 跳过（跳过须写理由） |
| 证据 | ✅ | 命令输出（含 EXIT 码）/ 文件路径 / 截图 / 网络包，三选一以上 |
| 自动化脚本 | ✅ | 脚本路径 + 断言名，或「手工」 |
| 执行人 / 日期 | ✅ | 谁在什么时候跑的 |
| 关联缺陷 | 选填 | `BUG-YYYY-NNNN`，失败时必填 |
| 备注 | 选填 | 刻意取舍、环境差异、待确认事项 |

**状态枚举**：`通过 / 失败 / 阻塞 / 跳过`。
**优先级枚举**：`P0 致命 / P1 严重 / P2 一般 / P3 轻微`。
**覆盖度枚举**（汇总用）：`✅ 已覆盖 / 🟡 部分覆盖 / ❌ 未覆盖`。

## 5. 填写示例（真实资产，照此颗粒度写）

### TC-PERM-002 · 客户端提交 owner_id 被服务端丢弃

| 字段 | 内容 |
|---|---|
| 用例编号 | TC-PERM-002 |
| 所属功能域 | 权限边界（对应 `07` §2 第 9 行） |
| 关联需求 / 规则 | `REQ-___`（由 `02` 补齐）/ `BR-___`「写入永不携带 owner_id，归属由服务端注入」 |
| 测试类型 | ☑ 接口　☐ 单元　☐ 集成　☐ E2E　☐ 验收 |
| 用例类别 | ☐ 正常　☐ 边界　☐ 异常　☑ 权限　☐ 并发　☐ 重复请求 |
| 优先级 | ☑ P1（归属伪造属权限边界，命中 `07` §5.3 阻塞阈值第 2 条） |
| 前置条件 | 已注册用户 A；已建团队 T 且 A 为成员；`GTD_TRUST_PROXY=0`；服务由 `tests/test_api.py` 真起、真库 |
| 自动化脚本 | `tests/test_api.py` — 归属伪造丢弃断言（49 项之一） |
| 关联缺陷 | 无（存量已通过） |

**测试步骤**
1. 以 A 的会话向创建工作项接口提交 JSON，额外携带 `"owner_id": "<另一个用户的 id>"`。
2. 读取该工作项，检查 `owner_id`。
3. 用另一用户 B 的会话尝试读取该工作项（验证没有因伪造产生越权可见）。

**预期结果**（可判定）
- 步骤 2：返回的 `owner_id` **等于 A 的 id**，不等于提交时伪造的值；HTTP 200。
- 步骤 3：若该工作项为个人域（`team_id IS NULL`），B 读取被拒或返回空数组；不产生任何归属漂移。
- `test_api.py` 对应断言为绿色，整体 `EXIT=0`。

**实际结果**
- 【实测·引用】既有记录：49 项全绿（113.7s）。**本次模板编制未重跑**；执行人须当场重跑并粘贴输出。

| 结论 | 证据 | 执行人 | 日期 |
|---|---|---|---|
| ☑ 通过（既有记录） | `python tests/test_api.py` 输出 + `EXIT=0` | 待执行人填写 | 待填 |

**备注**
- 关联 `README.md` §权限语义第 2 条与第 4 条：`work_items` 更新策略**不含** `owner_id 必须是我`，团队成员必须能推进别人建的工单，否则看板流转失效 —— **这是刻意取舍，不是缺陷**，改动前必须先读代码注释。

### 另一示例（并发类，写法对照）

### TC-CON-001 · 两进程共用一个 SQLite 库并发写入 40 次零失败

| 字段 | 内容 |
|---|---|
| 用例编号 | TC-CON-001 |
| 所属功能域 | 发布零停机（`07` §2 第 13 行） |
| 关联需求 / 规则 | `BR-___`「双槽位共用同一数据卷，切换不搬运数据」 |
| 测试类型 | ☑ 集成 |
| 用例类别 | ☑ 并发 |
| 优先级 | ☑ P0（蓝绿地基，总纲 §1 唯一硬阻塞相关） |
| 前置条件 | 两个 `server.py` 进程指向同一个 SQLite 文件；WAL + `busy_timeout=15000` |
| 自动化脚本 | `tests/test_zerodowntime.py`（9 项之一） |

**测试步骤**
1. 同时启动两个服务进程，共用同一个库文件。
2. 两进程各执行 20 次写入（共 40 次）。
3. 在 A 写入后立刻从 B 读取；在 A 建立会话后从 B 验证该会话有效。
4. 检查两进程回传的 `build` 是否可区分；扫描服务端日志有无锁冲突/异常栈。

**预期结果**（可判定）
- 40 次写入**零失败**；A 写入的内容 B 立刻读得到（非各自缓存）。
- A 的会话在 B 上有效（切流不登出用户）。
- 两个 `build` 可区分；日志中无 `SQLITE_BUSY` / `SQLITE_READONLY` / 异常栈。
- `EXIT=0`，【实测·引用】既有记录 9 项全绿 / 190.3s。

**实际结果** -（执行时填）

| 结论 | 证据 | 执行人 | 日期 |
|---|---|---|---|
| ☐ 通过 ☐ 失败 | `python tests/test_zerodowntime.py` 输出 | | |

**备注**
- 该用例耗时 190.3s，**必须单独跑**，超时阈值 ≥300s，不与 `test_api.py` 并行（`07` §4.2）。
- 平台差异：Linux 预期 `SQLITE_BUSY`（`busy_timeout` 自动等待），Windows 报 `SQLITE_READONLY`；应用层已统一兜底。**Linux 侧【未验证】**，首次上服务器必跑本用例（G6-02）。

## 6. 编写规范（质量门禁）

- [ ] **可判定**：预期结果能回答「通过 / 不通过」，不写「正常」「较快」「看起来没问题」。
- [ ] **可复现**：前置条件写全账号、数据状态、开关取值、端口（本机一律 `--noproxy '*'`）。
- [ ] **一条一焦点**：一条用例只验一个断言点；多个点拆成多条。
- [ ] **边界具体化**：不写「超长」，写「字段长度 4096 字符」；不写「多次」，写「15 分钟内 10 次」。
- [ ] **六类齐全**：正常 / 边界 / 异常 / 权限 / 并发 / 重复请求，每类至少 1 条（`07` §8.2）。
- [ ] **权限类必写预期拒绝结果**：越权用例必须写明「拒绝 / 返回空数组 / 403」中的具体一种。
- [ ] **目录穿越用例必须 `--path-as-is`**，否则是假检查（`07` §1.4）。
- [ ] **失败即开单**：任何「失败」结论都要有 `BUG-YYYY-NNNN` 编号。
- [ ] **防复发**：P0/P1 缺陷修复后，必须新增一条用例并挂 `TC-` 编号（`07` §4.3）。
- [ ] **证据不编造**：【实测·引用】/【未验证】/【文档示例】/【待裁决】四态如实标注（`07` §0.1）。
