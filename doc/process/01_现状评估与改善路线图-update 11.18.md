| 项 | 结果 |
|---|---|
| 每请求 `request_id` | ✅ 8 位十六进制，客户端拿到的错误编号能直接反查日志 |

现在两件都能用结构化查询回答。

### 5.1 本轮新发现的缺陷：REQ-039（**已修复**，本节保留发现过程作教训留档）

> **当前状态（实测复核）**：REQ-039 已修复 —— `js/app.js:825` 的 `case 'nav'` 已加 `state.filters = {}`，并有回归断言 `.smoke/app-boot-test.mjs:416-435`（[5b]：先设 `itemType=inspection` 再 nav 到 desk，断言不出现假"队列已清空"、事件类事项仍显示），本版实跑全绿【代码·已核】。以下分析是"当时如何发现"的记录，**不再是未修缺陷**；§6 P1 与 §9 U-B 已同步。

**跨视图筛选串味（发现当时的样子）。** `js/app.js` 的 `case 'nav'` 当时是：

```js
case 'nav': {
  state.view = ds.view
  state.search = ''
  if ($('#global-search')) $('#global-search').value = ''
  saveUiPrefs()
  ...
```

**只清 `state.search`，没有重置 `state.filters`。**

根因比"忘了重置"更具体：**两个视图共用同一个筛选键**。

```
views.js  viewTeamRoutine:  state.filters?.itemType || 'all'
views.js  viewTeamDesk:     state.filters?.itemType || 'all'    ← 同一个键
app.js    'switch-space' / team-select:  state.filters = {}     ← 只在这两处清
```

`routine` 的筛选标签把 `filters.itemType` 写成 `'inspection'`；切到 `desk` 后，`desk`
拿**同一个键**去过滤 `['incident','request','change','problem','event']` → **交集为空**
→ 渲染出「队列已清空。」

**当时列的两个修复选项**（§9 U-B 曾给建议，现已关闭）：
① `case 'nav'` 里加 `state.filters = {}` —— 最简，但牺牲「来回切换保留筛选」的体验；
② 每个视图用独立键命名空间（`routine.itemType` / `desk.itemType`）—— 更彻底。
**实际采用 ①**（`js/app.js:825`，已落地并有回归断言）。

**为什么当时（409 项，现 430 项）的前端测试抓不到它**：`render-test` 分别测了 routine / desk
**各自带 filter 渲染**，但**没有任何用例"先设 filter 再切视图"**。测的是"能渲染"，
不是"切过去还对"。**该缺口已补**：`app-boot-test.mjs:416-435` 的 [5b] 现在专测"先设 filter 再切视图"。

对应 PRD 的 GAP-20 / REQ-039 / AC-F-39。P0 批次（P0-1~P0-8）**没有覆盖它**：
那批修的是 REQ-036/037/038，REQ-039 不在其中。

> 这条值得单独标：**它是"反推出的需求"里唯一一条被确认为未兑现的**。
> 其余 3 条元需求都在 P0 批次修好了。

## 8. 本轮教训

1. **"测量方法错了"两个方向都会错。** 本轮出现两次：一次假通过（`awk` 引号报错 → 两变量空串 →
   `空 == 空` 判"不变"）、一次假失败（`node x.mjs | tail -1` → SIGPIPE 让 Node 崩溃，
   五套"全部失败"其实是管道问题）。**"验出失败"和"验出通过"都不能直接采信。**

2. **Windows 绿 ≠ Linux 绿。** 结构化日志第一次发布被 L0 门禁拦住：Windows 155 全绿、Linux 1 条红。
   根因是 `NotADirectoryError`(Linux) vs `FileNotFoundError`(Windows)。**WSL 就是 Linux，多跑一遍的成本只有一条命令。**

3. **`wsl.exe` 传多行内联脚本不可靠**（函数定义、`$var`、引号都会被字面传递）。踩了三次，
   以后一律写脚本文件到 `/mnt/d/...` 再执行。

4. **测试存在 ≠ 测试被执行。** `contract-test` 39 项写好很久，一直没进 L1 列表；
   L1 本身因为没 node 长期空转。**"门禁里有这项"和"这项真的会跑"是两件事。**

5. **文档写得比代码松，和文档写得比代码严，都要修。** 本轮 07/08/09 的错都是前者（说"只 warn"，
   实际早就是 `die`）；后果是让人做无谓复核，久了就没人信门禁。
