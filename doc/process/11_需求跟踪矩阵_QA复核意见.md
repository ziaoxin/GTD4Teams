### 1.3 🟡 REQ-033 —— 证据不覆盖论点

| | 内容 |
|---|---|
| 产品经理版 | `✅`，测试证据：「app-boot-test『index.html 不引用任何外部脚本』『已彻底移除云服务 SDK 的引用』」 |
| QA 判定 | **`⚠️`** |

**理由**：该 REQ 的主张是「**零第三方依赖**（Python 标准库单体）」。
而所引证据断言的是**前端 HTML 不含外部 `<script src="http...">`** —— 这是**前端外链**，与 **Python `import` 是否引第三方** 是两个不同的失效模式：

- `import requests` 不会让 `index.html` 出现任何外链
- 反之，`index.html` 无外链也不阻止后端引入第三方包

**实际状态**：QA 已逐条核对 `pyapp/*.py` 与 `server.py` 的全部 import，**确认均为标准库**（os / json / sqlite3 / hashlib / hmac / http.server / ssl / urllib / http.cookies / email.utils / argparse / base64 / binascii / ipaddress / secrets / socket / signal / sys / re / threading / time / tempfile / webbrowser / collections / pathlib / datetime / logging / traceback）。
**结论：事实成立，但无自动化断言守着** —— 引入一个 `import requests` 不会被任何门禁拦住。故 `⚠️`。

> 这不是抠字眼：本例正是"证据看起来相关、实际不覆盖论点"的典型。若要升 ✅，应加一条扫描 `pyapp/` 与 `server.py` 的 import 白名单断言（成本约 15 行）。

## 4. 主理人已裁决事项（须在任一版本中留存）

以下决定由主理人 2026-11-18 作出，**目前无任何文件承载**（原 QA 版 §4.4 随覆盖丢失），特此登记：

**REQ-039 修复采用「甲」方案**：`case 'nav'` 里加 `state.filters = {}`。

- **甲修的是 bug，乙修的是体验。** 切视图后假空并显示「队列已清空」是**错误信息**，必须止血；「切回来还记得我刚才的筛选」是优化，不是正确性。顺序应**先修正确性、再谈体验**。
- **乙（按视图隔离筛选命名空间）不是"改 6 处读取点"那么简单**：若做视图状态持久化，**必须同时决定 `state.search` 是否也按视图隔离**，否则会出现"筛选按视图记、搜索不按视图记"的半吊子状态。那是独立特性，应统一设计，不夹带在 bugfix 里。
- BR-029 原文允许两种做法（「或按视图隔离筛选命名空间」），**选甲不违反 BR-029**。
- **甲落地验收判据**：设 `filters.itemType='inspection'`（`routine`）→ 触发 `case 'nav'` 切到 `desk` → 断言输出**不含**「队列已清空」。用例须与修复**同批提交**（红灯 → 绿灯）。

### REQ-039 缺陷机制（供修复者参考）

```
app.dispatch['nav']           只做 state.view = ds.view + state.search = '' + 清 #global-search
                              （无 state.filters 重置）        ← 同空间内切视图
app.dispatch['switch-space']  state.filters = {}              ← 只在个人↔团队切换时清
#team-select change            state.filters = {}              ← 只在切团队时清
normalizeView()               不动 filters
```

**假空成因**：两个视图**共用同一个筛选键** ——

```
views.viewTeamRoutine:  const filter = state.filters?.itemType || 'all'
views.viewTeamDesk:     const filter = state.filters?.itemType || 'all'
```

`routine` 写入 `filters.itemType='inspection'`；切到 `desk` 后拿**同一个** `itemType` 去过滤 `['incident','request','change','problem','event']` → **交集必然为空** → 渲染「队列已清空」。
与 PRD 自身 GAP-20 的描述独立吻合。

**现有测试为何测不出**：`render-test` 分别测了 routine 带 filter、desk 带 filter，各自都正常；**没有任何用例"先设 filter 再切视图"**，而缺陷只在这条路径上。
